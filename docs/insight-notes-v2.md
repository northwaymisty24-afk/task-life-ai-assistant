# 经验本与日记：12 月 20 日交付补充说明

状态：产品负责人的新增需求与前端原型方案；后端表结构、接口及排期需 A/B/C 联调确认。项目交付目标由产品负责人调整为 **2026-12-20**。本文替代原“下一版经验本提案”，不直接改写已评审的 PRD、SPEC 或共享契约。

## 1. 用户决定什么值得收进经验本

日记按日期记录当时发生的事和感受；经验本收藏用户以后还想翻看的话。两者允许重叠，**收录是额外收藏，不是迁移或互斥分类**。

合格的日记片段仍按 PRD 3.7 默认留存，不需要用户回复确认才能保存感想。经验本必须由用户主动新增或确认候选才写入。没有点击“收录”，不影响日记留存。原话始终独立保存，整理稿不能覆盖原话。

| 表达 | 日记 | 经验本 |
| --- | --- | --- |
| “今天风很舒服。” | 保留日记原话 | 默认不新增；用户想收藏也可以 |
| “我上午专注，下午到晚上容易涣散。” | 保留当天观察 | 可由用户收藏到自定主题“自己的节奏”；不据此推断永久画像或健康结论 |
| “下次先写粗稿，再慢慢改。” | 表达中有感想则正常保留 | 用户可选这一句收藏，不自动创建任务 |
| 对人物偏好、人情社交、抽象生活感悟的记录 | 有日期与来源，可正常回看 | 都允许收藏；主题不限于知识或操作方法 |
| 一段话同时有任务、感受与经验 | 原始表达保持完整，任务按独立规则处理 | 只收用户确认的范围；不要求把整段塞进单一类别 |

划选能提高“收哪段”的准确性，不能证明内容本身客观正确。经验属于用户的私人记录，可随时修订，不自动当作模型事实或长期画像。

## 2. 页面入口

导航新增独立“经验本”，与待办、习惯、聊天、晚间日记、周回顾并列。保持纸底、圆体标题与手绘图标。

- **聊天**：消息下方增加“收进经验本”。同一条允许分次挑出不同句段。快捷开头“经验总结”表达收录意图，发送后打开确认表，取消不影响聊天原文。日记留存与任务识别仍各自处理。
- **晚间日记**：保持“今日回顾 → 此刻的感受 → 安排明天”。在此刻感受文本框下方放小字“选一段，收进经验本”。右侧增加“一起理理明天”窗口，点击进入聊天，预填“帮我安排明天（具体日期）的任务：”，不自动发送、不凭跳转直接建任务。原有手动添加与排序继续可用。
- **经验本**：顶部只放搜索和“＋ 记一笔”，下方是主题筛选和笔记列表；点击条目查看全文、来源并编辑。新建时直接弹出同一张表，不长期摆一个聊天式输入框。正文必填，标题与主题可不填。
- **主题**：用户可任意命名，例如“自己的节奏”“写作”“喜欢的小店”，也可未分类。本次先一条一个主题，支持改主题、按主题筛选；不做多级目录、复杂标签体系。

## 3. 从底部弹出的收录表

1. 显示只读来源原话。用户可用鼠标划选，手机长按选区，点击“使用选中的原话”。未划选时允许收录整段，明确显示“暂选整段”。
2. 下方“收录内容”可修改；原文不随修改而变化。可填可不填的标题、自定义主题和来源日期放在同一张表内。
3. 用户点击“确认收录”后才新增经验条目。取消、关闭或忽略建议均不写经验。
4. 再次打开可调整范围与正文、改主题；“撤出经验本”保留日记及聊天原话。相同来源、范围与内容重复确认应去重。

日记尚未保存时，当前原型保存经验引用的原文快照，不虚构已落库的日记 ID。真实后端必须先持久化来源草稿或独立原始表达，再创建可追溯引用。之后修改日记不能使旧选区悄悄指向错误句子。

## 4. 本次范围与模型、录音

**本次建议必交**：独立经验本，三种录入入口，划选与编辑，自定主题、搜索、来源回看、撤出，后端持久保存、身份隔离、去重与来源删除联动。

**有余力再交**：模型从自由聊天或此刻感受中建议一段值得收录的原话；用户可改范围、改整理稿、选主题、忽略。建议只在合适时机出现，篇幅长不是强制弹出的理由，候选不落为正式经验。

“录音转文字”和“文字整理”是独立能力。先用已有公众号语音识别或用户粘贴转写稿即可进入同一收录流程；H5 新增录音、转写供应商、音频存储不是完成经验本的前置条件。ima 或其他服务是否有适合项目调用的接口、权限与费用，需要技术负责人核实后选择；本补充不承诺已接入任何供应商。模型整理应只生成可修改候选，不添加原话没有的推断。

## 5. 数据与接口建议（待契约评审）

保留日记与原始输入的数据模型；新增独立 `insights` 区域。复用现有 Python 与 SQLite 即可表达基础 CRUD，无需为这个功能更换数据库。

| 字段 | 规则 |
| --- | --- |
| id, user_id | 条目与所属用户；user_id 由服务端会话确定 |
| source_type | chat / diary / manual |
| source_event_id / source_reflection_id / source_version | 可空；非手动录入应指向已持久化、同用户的来源与版本 |
| quote_start, quote_end, quote_text | 连续选区及精确原话；不可覆盖原始表达 |
| title, body | 用户可修改的标题与收录正文；body 可与 quote_text 不同 |
| topic | 用户自定或空；服务端控制长度，避免无限新增垃圾标签 |
| created_at, updated_at, revoked_at | 新增、修订、撤出时间 |
| request_id / idempotency_key | 重试不能生成重复经验 |

建议接口：GET/POST `/api/v1/insights`，PATCH/DELETE `/api/v1/insights/{id}`。列表支持关键词、主题与游标分页。DELETE 表示撤出经验；彻底删除来源按 Q-13 处理引用、派生文本、缓存，不能靠经验副本绕过删除或回顾排除。

前端 textarea 选区使用 JavaScript **UTF-16 code unit、左闭右开区间**。Python 服务端不要直接把同一数字当 Unicode 码点切片，必须转换并校验 `quote_text`，包括 emoji、换行与重复句子。服务端校验来源版本、范围与所属用户；不能只相信前端传来的原话。

日记的 `include_in_review=false` 必须向来源经验的所有回顾、观察候选和派生结果传播；经验本不自动写画像、安排、习惯或提醒。

## 7. 当前交付状态与验收

本次新增独立 HTML 前端原型，以用户提供的 `little-days-h5 (2).html` 为底。原型实现直接记一笔、聊天与此刻感受划选、标题与自定主题、搜索筛选、编辑撤出、来源快照、聊天安排明天草稿入口；数据仅存当前浏览器。浏览器已检查三种新增入口、选区、主题和刷新留存。尚未接后端、模型或录音，不代表多人数据与真实自动识别已完成。

联调重点：普通感受默认进日记但不自动进经验；同一段可同时属于两处；重复确认不重复写；emoji 选区正确；改原文可追溯旧版本；撤出经验不删日记；删除/排除原话时经验不泄漏派生结果；外部账号无法读取、编辑或引用他人来源；整理失败可保存原话，取消候选不丢日记；从晚间日记跳聊天不自动发送、不凭空建任务。
